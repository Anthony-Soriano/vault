## Settled implementation details (within approved scope)

- **`todo_marker` detection is filename-based** (files named `TODO`/`TODOS`/`FIXME`/`FIXMES` with common text extensions), not a content scan. Reading every file to grep comments would violate the "targeted, not whole-repo" principle and the discovery cost budget. Content-level TODO extraction is a later enhancement, not v0.3.1.
- **Determinism split:** `ProjectEvidenceInventory` and `ProjectTruthReadiness` carry **no timestamps** → byte-identical for identical input with no clock. `AiContextPackage.createdAt` and `ProjectContextAnalysis.generatedAt` use an injected clock (`now`), exactly like `createAiContextPackage`/`AiService`; determinism tests fix the clock.
- **Context selection is pure and bounded.** `selectContextEvidence(inventory)` returns a deterministic, capped list of relative paths (priority: project_truth → manifest → schema_migration/config → docs → representative source), capped at `CONTEXT_MAX_ITEMS`. Storage reads only those files' content, each truncated to `CONTEXT_MAX_CHARS`, text-like only. This guarantees "targeted, not whole repository."
- **Discovery degrades, not throws, at the cap.** Reconcile throws past 25,000; discovery instead stops and sets `truncated: true` (analysis must not hard-fail on a big repo).
- **Placement mirrors `analyzeIntegrity`:** `SqliteVaultRepository.analyzeProjectContext(projectId)` performs fs discovery + bounded reads and composes the pure core analyzers; `VaultService.context.analyze(projectId)` validates the id (`assertIdentifier`) and delegates. Pure functions stay fs/SQLite-free in `vault-core`.
