# v0.3.2 — Project Truth Bootstrap

Status: **Approved design** (2026-08-07). Base: `main` at `b76fc62` (tag `v0.3.1`, Phase 3 Project Context & Repository Analysis); baseline standing gate green (100/100). Scope: Phase 3 release slice **`v0.3.2`**, activated for design/planning by owner approval (see `.orbit/CURRENT_PHASE.md`, `.orbit/DECISIONS.md`, `.orbit/ROADMAP.md`). This document is design only — no implementation code is written until the execution plan is complete and consistent with Project Truth.

## Goal

Give Vault the ability to **draft missing Project Truth** from repository evidence: run the deterministic `v0.3.1` context analysis, send targeted, transparent context through the `v0.3.0` proposal pipeline to a provider, and return **evidence-backed, non-canonical, ephemeral** Project Truth drafts. Each draft cleanly separates **inferred technical facts** (cited to evidence that actually exists in the supplied context) from **owner-intent gaps** (surfaced as explicit "needs owner input", never fabricated). It delivers the roadmap capability **PC-02** (evidence-backed Project Truth bootstrap).

Data flow, in order:

1. **Analyze** — reuse the read-only `v0.3.1` `analyzeProjectContext` to get the inventory, readiness verdict, and a targeted `AiContextPackage`.
2. **Plan (pure)** — from readiness, decide which required `.orbit/` documents to target and their state (`missing` / `partial` / `present`), and their suggested disposition (`create` / `merge` / `keep_existing` / `skip`).
3. **Generate** — drive the existing `AiService.propose(...)` with `desiredKind: "project_truth"` and per-target instructions that enforce the evidence boundary.
4. **Map + validate (pure)** — turn each returned `AiProposal` into a `ProjectTruthDraft`; validate every cited evidence ref against the supplied inventory (decision 3), separating verified technical facts from owner-input gaps.
5. **Inspect** — return an ephemeral `ProjectTruthBootstrapResult` to a **read-only** renderer view. Nothing is persisted; there is no write/approve path.

## Owner-approved decisions (2026-08-07) — binding

Copied from `.orbit/CURRENT_PHASE.md` / `.orbit/DECISIONS.md`; the design is built around these.

1. **Existing-stack boundary:** bootstrap + structural gap-fill only; existing docs stay authoritative by default; deep staleness / change / maintenance proposals are `v0.3.5`. Do not pull the maintenance engine in.
2. **Ephemeral drafts:** no proposal store/DB, no canonical writes, no approve/edit/save/merge/replace execution. Persistence/review/approval/lifecycle/audit are `v0.3.3`.
3. **Evidence validation:** a citation is trusted only if its `ref` resolves to evidence actually present in the supplied context inventory/package; unverifiable refs are never presented as evidence-backed technical facts.
4. **Existing-state disposition:** existing authoritative Project Truth defaults to `keep_existing`; emit no replacement/change recommendations (that would be `v0.3.5` behavior).

## Non-goals (deferred, tracked in Project Truth, not silent gaps)

- **Proposal persistence / proposal store / any new DB table** — drafts are ephemeral (decision 2).
- **AI proposal review & approval** (`v0.3.3`) — no approve/edit/save/merge/replace execution, no review UI, no history/audit of proposals.
- **Knowledge Proposal Engine** (`v0.3.4`).
- **Project Truth Maintenance** (`v0.3.5`) — no staleness/conflict/change detection over an evolving project; no change/replacement recommendation for an existing authoritative stack (decisions 1 & 4).
- **Canonical mutation** — no writes to knowledge, documents, or `.orbit/` files; no file-write IPC.
- **A live vendor provider** — the gate runs against `StubAiProvider`; no provider decision is made and none is baked in.
- **Autonomous/background generation** — bootstrap is explicit/triggered only.
- **Any change to `v0.3.0`/`v0.3.1` contracts or invariants** — this slice is additive.

## Binding invariant — Planner authority over bootstrap scope (owner-added 2026-08-07)

**The planner is the sole authority over bootstrap scope.** `planProjectTruthBootstrap` alone owns:

- **which documents exist** (derived from the read-only `ProjectContextAnalysis` readiness);
- **which documents are targeted** for generation;
- **document state** (`missing` / `partial` / `present`);
- **generation scope** (the set of create-targets).

The AI **fills those predetermined slots only.** The AI may generate content **only** for planner-selected targets, and may **never**:

- invent additional Project Truth documents outside the planner's target set, **nor**
- silently skip / omit a planner-selected target.

This is enforced structurally in `mapBootstrapDrafts`: drafts are produced **by iterating the planner's `targets`**, never by iterating the provider's proposals. A proposal that does not correspond to a planned create-target is **discarded** (it can never introduce a new document); a planned create-target that received no proposal is still emitted as a draft (it can never be silently skipped) with `proposal: null` and an owner-input note. `AiService.propose` cannot widen scope because the target set is fixed before generation and the mapping is keyed off the plan, not the response. Acceptance criterion 4 and the mapper tests assert this.

## Future hardening (documented, NOT implemented in v0.3.2)

These are recorded as forward-looking design notes only. Implementing them now would expand scope — do **not**.

- **Proposal ↔ target identification.** v0.3.2 pairs the *nth* create-target with the *nth* proposal. This is acceptable **only** because generation runs against the deterministic `StubAiProvider` and the planner authority invariant above already guarantees no document is invented or skipped regardless of pairing. It is an **implementation detail of v0.3.2, not a durable contract.** The long-term architecture should identify each proposal by an explicit stable identifier (e.g. a `targetDoc` field echoed back on `AiRawProposal`/`AiProposal`) and map by that identifier rather than by provider response ordering — so a non-deterministic or reordering provider cannot misattribute a draft. This becomes relevant when a live, non-stub provider is introduced.
- **Rule version semantics.** `PROJECT_TRUTH_BOOTSTRAP_RULE_VERSION = "1"` is an acceptable anonymous integer for v0.3.2. As bootstrap logic evolves, future rule versions should become explicit semantic/versioned identifiers (e.g. a documented scheme distinguishing planner-rule changes from mapper-rule changes) rather than an opaque incrementing integer, so consumers can reason about what a version change means. No change now.

## Product principles & invariants honored

- **AI only proposes (invariant 3).** Every draft is an `AiProposal` with `status: "proposed"`; the slice contains no canonical-write path at all — the guarantee is structural (absence of the code), not conventional.
- **Provenance is mandatory.** `AiService` already rejects a proposal that has neither cited evidence nor an explicit `inferred` flag (`AI_RESPONSE_INVALID`). v0.3.2 additionally validates that cited refs resolve to real inventory paths (decision 3).
- **Provider neutrality.** Generation goes through `AiModelProvider`; `StubAiProvider` drives tests/gate; no vendor is baked in.
- **Project isolation (invariant 5).** `AiService` rejects `context.projectId !== request.projectId` (`AI_PROJECT_ISOLATION`); each draft's `projectId` is stamped from the request; `analyzeProjectContext` is project-scoped.
- **Renderer never touches Node/SQLite/fs (invariant 2).** All fs stays in main/storage (the reused `analyzeProjectContext`); the renderer only calls `window.vault`.
- **No direct DB access by AI (invariant 8).** `AiService` and the bootstrap orchestrator hold **no repository**. `VaultService` composes a read-only repo call with a repo-free AI call, passing only context.
- **Determinism where possible (invariant 7).** The `v0.3.1` analyzers stay byte-deterministic; the bootstrap **planner** and the **draft-mapping/validation** are pure functions. Only the model call is non-deterministic, and it is clearly AI-labeled.

## Architecture

Same strict one-directional boundary. New surface is **additive**; the only structural change is composing the existing `AiService` into `VaultService` for the first time (optional dependency). No existing channel, table, or invariant changes.

```
Renderer (window.vault.projectTruth.bootstrap — read-only inspection view)
  → typed IPC ("vault:project-truth:bootstrap", NON-MUTATING, no `mutates`, no vault:changed)
  → VaultService (packages/vault-core) — validation + orchestration (holds repository + optional AiService)
        ├─ repository.analyzeProjectContext(projectId)   [v0.3.1, read-only fs discovery]  → ProjectContextAnalysis
        ├─ planProjectTruthBootstrap(analysis)           [pure core]                        → BootstrapPlan
        ├─ AiService.propose({ ..., desiredKind:"project_truth" })  [v0.3.0, repo-free]     → AiProposal[]
        └─ mapBootstrapDrafts(plan, proposals, inventory) [pure core]                       → ProjectTruthDraft[]
  → ProjectTruthBootstrapResult (ephemeral; NOT persisted)
```

**Placement rationale:**
- **Fs discovery** is untouched — the existing `analyzeProjectContext` in `packages/vault-storage` already walks `projects/<id>/` read-only with ignore-lists, the 25,000-entry cap, symlink safety, and bounded content reads, and builds the targeted `AiContextPackage`. v0.3.2 reuses it wholesale (**target: zero storage change**).
- **Pure logic** (target planning; draft mapping + citation validation) lives in `packages/vault-core` as pure functions over plain structs — byte-deterministic and unit-testable exactly like `classifyEvidence` / `analyzeKnowledgeIntegrity`.
- **Orchestration** lives in `VaultService` — the only sanctioned service boundary ("AI uses Vault's service/API boundaries", ROADMAP). It reads (read-only), plans, calls `AiService`, and maps — passing **only context** to the AI layer, which keeps holding no repository.
- **Generation** is the existing `AiService` — unchanged. It already enforces status, provenance, isolation, and typed provider failures.

### `packages/vault-types` — contracts (additive)

Reuses the existing `AiProposal` / `AiProvenance` / `AiEvidenceRef` / `AiContextPackage` / `ProjectTruthReadiness` verbatim. New (final names fixed in the execution plan):

- `ProjectTruthDocState = "missing" | "partial" | "present"` — the state of one required `.orbit/` document.
- `ProjectTruthDisposition = "create" | "merge" | "replace" | "skip" | "keep_existing"` — the PRODUCT_SPEC owner outcomes, carried as a **suggestion only** (never executed in v0.3.2; `replace` is defined for contract completeness but v0.3.2 never suggests it for an existing stack — decision 4).
- `ProjectTruthDraft` — `{ targetDoc: string; docState: ProjectTruthDocState; suggestedDisposition: ProjectTruthDisposition; proposal: AiProposal | null; verifiedEvidence: AiEvidenceRef[]; ownerInputNeeded: string[]; }`. `proposal` is `null` for a `keep_existing`/`skip` target that generated nothing. `verifiedEvidence` is the subset of the proposal's evidence whose `ref` resolved against the supplied inventory (decision 3).
- `ProjectTruthBootstrapResult` — `{ projectId: string; ruleVersion: string; readiness: ProjectTruthReadiness; drafts: ProjectTruthDraft[]; unresolvedInfo: string[]; provider: string | null; model: string | null; generatedAt: string; }`.
- IPC contract entry on `VaultRendererApi`: `projectTruth: { bootstrap(projectId: string): Promise<ApiResult<ProjectTruthBootstrapResult>> }`.

The result reuses the `AiError` codes (`AI_NOT_CONFIGURED`, `AI_PROVIDER_ERROR`, `AI_TRANSPORT_ERROR`, `AI_RESPONSE_INVALID`, `AI_PROJECT_ISOLATION`, `AI_VALIDATION_ERROR`) surfaced through the existing `ApiResult<T>` error channel — no new error codes.

### `packages/vault-core` — pure planner + orchestration

- `PROJECT_TRUTH_BOOTSTRAP_RULE_VERSION` — version tag stamped into every result (mirrors `PROJECT_CONTEXT_RULE_VERSION`), so a stability test can assert the planner is deterministic.
- `REQUIRED_TRUTH_DOCS` is reused from the existing v0.3.1 module (the canonical seven `.orbit/*.md`) — one source of truth for "what a complete stack is".
- `planProjectTruthBootstrap(analysis: ProjectContextAnalysis): BootstrapPlan` — **pure**. From `readiness`, produce one planned target per required doc: `docState` (present → from `presentDocuments`; else `missing`; `partial` is the whole-stack state, expressed per-doc as `missing` for the absent ones), a `suggestedDisposition` (missing → `create`; present → `keep_existing`), a per-target `purpose` + `instructions` string encoding the evidence-boundary rule, and the subset of context items relevant to that target. Present docs get **no generation** (decision 4). Deterministic and clock-free.
- `mapBootstrapDrafts(input: { plan; proposals: AiProposal[]; inventory: ProjectEvidenceInventory }): { drafts; unresolvedInfo }` — **pure**. For each planned target, attach the matching proposal (if any), then **validate citations** (decision 3): keep only `evidence[]` entries whose `ref` matches a `relativePath` in `inventory.items`; move the rest into `ownerInputNeeded` (never presented as fact). Aggregate `unresolvedInfo` from proposals flagged `inferred` and from targets with no citable evidence. Keyed by `targetDoc` so duplicate proposals for one doc collapse deterministically.
- `ProjectTruthBootstrapService` — async orchestrator; constructor takes an `AiService` and **no repository**. `bootstrap(analysis)`: runs `planProjectTruthBootstrap`, calls `aiService.propose(...)` for the targets that need generation (one call carrying the targeted context, `desiredKind: "project_truth"`, and merged instructions), then runs `mapBootstrapDrafts`, and assembles the `ProjectTruthBootstrapResult` with an injected clock. On any `AiService` error it returns that typed error unchanged (nothing mutates).
- `VaultService` — constructor gains an **optional** second arg: `new VaultService(repository, options?: { ai?: ProjectTruthBootstrapService })`. Existing `new VaultService(repository)` still compiles and behaves identically (AI-disconnected acceptance holds). New facade: `projectTruth = { bootstrap: (projectId) => … }` — validates the id (`assertIdentifier`), returns `AI_NOT_CONFIGURED` if no AI is configured, else calls `repository.analyzeProjectContext(id)` (read-only) and delegates to the bootstrap service. Performs no writes.

### `packages/vault-storage` — no change (target)

`analyzeProjectContext` already provides the inventory, readiness, and a targeted `AiContextPackage`. v0.3.2 consumes it as-is. If per-target content selection proves too coarse under test, the *minimal* fallback is a read-only variant that returns already-selected file contents keyed by path — still read-only, still behind the storage boundary, no writes. Prefer reuse; add only if a test proves it necessary, and record the deviation in the plan.

### `apps/vault-desktop` — wiring + read-only inspection surface

- `electron/main`: compose the AI layer at Vault activation — `new VaultService(repository, { ai: new ProjectTruthBootstrapService(new AiService(new StubAiProvider())) })` (provider-neutral; the stub is the default backend until a live provider is chosen). Register `vault:project-truth:bootstrap` via the existing `handle(channel, op)` helper with **no `mutates`** (non-mutating: emits no `vault:changed`).
- `electron/preload`: expose `window.vault.projectTruth.bootstrap(projectId)` through the existing `call<T>` wrapper on the frozen surface.
- `renderer`: a **read-only** `ProjectTruthBootstrapView` (mirroring `ProjectContextView`): a "Generate Project Truth drafts" trigger, then per-draft display of target doc, `docState`, `suggestedDisposition`, **verified technical facts** (cited evidence, distinct styling), **owner-input-needed** gaps (distinct styling), and provider/model provenance. **No approve/edit/save/merge/replace controls.** Displaying a draft is not persisting it.

## Acceptance-criteria → test mapping

Mirrors `.orbit/CURRENT_PHASE.md` "Acceptance criteria (v0.3.2)". New suite `tests/phase3-project-truth-bootstrap.test.ts`:

1. **Proposal-only** — every draft's `proposal.status === "proposed"`; no code sets canonical status.
2. **Provenance** — a stub raw proposal with empty evidence + `inferred:false` yields `AI_RESPONSE_INVALID` (enforced by the reused `AiService`); a valid draft carries either cited evidence or `inferred:true`.
3. **No mutation / no write path** — a full `VaultSnapshot` (or repository state) is byte-identical before and after `bootstrap`; grep/inspection confirms no repository write and no mutating IPC.
4. **Three states** — fixtures: `missing` (empty `.orbit/`) drafts all required docs with `create`; `partial` (some docs) targets only the missing ones and leaves present ones `keep_existing`; `complete` defaults every doc to `keep_existing` with `proposal: null` and no change recommendation.
5. **Evidence validation (decision 3)** — a stub proposal citing a `ref` **absent** from the supplied inventory is not presented as `verifiedEvidence`; the claim moves to `ownerInputNeeded`. A citation matching a real inventory path stays in `verifiedEvidence`.
6. **Project isolation** — a context package whose `projectId` differs from the request → `AI_PROJECT_ISOLATION`; each draft's `projectId` equals the requested id.
7. **AI failure / not configured** — a provider that throws → typed `AI_PROVIDER_ERROR`/`AI_TRANSPORT_ERROR`, state unchanged; `VaultService` with no AI configured → `AI_NOT_CONFIGURED`.
8. **Non-mutating IPC contract** — `scripts/phase2-lifecycle-ui-regression.mjs` asserts `vault:project-truth:bootstrap` exists, carries no `mutates` flag, and is wired through preload to `window.vault.projectTruth.bootstrap`, with the renderer view mounted.
9. **Repository-free AI** — `ProjectTruthBootstrapService`/`AiService` constructed with no repository; structural test that the bootstrap service exposes no persistence handle.
10. **Deterministic planner** — `planProjectTruthBootstrap` returns byte-identical output for identical `ProjectContextAnalysis` input (no clock); `mapBootstrapDrafts` is likewise pure.
11. **Read-only UI** — regression asserts the view has no approve/edit/save/merge/replace controls (copy/handler absence).

## Risks (from `.orbit/CURRENT_PHASE.md`)

- **Scope creep into `v0.3.3`/`v0.3.5`** — keep drafts ephemeral (no store), execute no owner action, emit no change/replacement recommendation for an existing stack. Structural guards make drift require new, reviewable code.
- **AI gaining implied persistence** — keep `AiService`/orchestrator repository-free; `VaultService` passes only context; assert by construction.
- **Fabricated citations as facts** — validate refs against inventory paths; downgrade unresolved refs to owner-input-needed (decision 3).
- **Fact/intent blur in UI** — render cited evidence distinctly from owner-input gaps.
- **Non-determinism vs. the gate** — gate runs against the stub + fixed clock; assert shape/invariants/mapping, not prose.
- **Provider-decision pressure** — ship against the neutral interface + stub; a live provider is a later config/ops step, not a contract change.
- **Large repositories** — reuse the capped, read-only `analyzeProjectContext`; do not solve BL-06 here.
