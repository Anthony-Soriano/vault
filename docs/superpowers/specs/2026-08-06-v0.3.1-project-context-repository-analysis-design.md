# v0.3.1 — Project Context & Repository Analysis

Status: **Approved design** (2026-08-06). Base: `main` at `36ee83a` (tag `v0.3.0`, Phase 3 AI Foundation), verified in sync with `origin/main`; baseline standing gate green (85/85). Scope: Phase 3 release slice **`v0.3.1`**, activated by owner approval (see `.orbit/CURRENT_PHASE.md`, `.orbit/DECISIONS.md`, `.orbit/ROADMAP.md`). This document is design only — no implementation code is written until the execution plan is complete and consistent with Project Truth.

## Goal

Give Vault a **deterministic, local-first** mechanism to understand what evidence exists in a project and to construct controlled, transparent context for AI — **without** generating Project Truth, invoking a live model, creating proposals, or mutating canonical state. It delivers the roadmap foundations for **PC-01** (Project Truth readiness scan) and **PC-04** (context package for AI).

Three capabilities, in order of data flow:

1. **Evidence discovery** — walk a project's managed files and produce a deterministic inventory of the evidence that exists.
2. **Classification + Project Truth readiness detection** — label each evidence item by technical-fact category, and classify the project's Project Truth stack as `complete` / `partial` / `missing` / `duplicated` / `potentially_stale`.
3. **Context package construction** — assemble a **targeted** `AiContextPackage` (reusing the existing `v0.3.0` contract) from selected evidence, each item source-traceable.

Plus a **read-only inspection surface** (owner-confirmed 2026-08-06) so the owner can actually see the inventory, readiness verdict, and context package.

## Non-goals (deferred, tracked in Project Truth, not silent gaps)

- **Project Truth Bootstrap / draft generation** (`v0.3.2`, PC-02) — no drafting of PROJECT/PRODUCT_SPEC/ARCHITECTURE/etc. content, no none/partial/existing draft outcomes, no Create·Merge·Replace·Skip.
- **AI proposal review/approval** (`v0.3.3`) — no review UI, no approval gate here.
- **Knowledge Proposal Engine** (`v0.3.4`) and **Project Truth Maintenance** (`v0.3.5`).
- **Live model invocation to generate content.** `v0.3.1` *builds* the context package; it does not send it to a provider to produce anything. No live vendor provider.
- **Canonical mutation.** No proposals persisted, no knowledge/document/Truth writes. The analysis is pure/read-only with respect to Vault state.
- **Autonomous/background scanning.** Analysis is explicit/triggered, not watcher-driven or scheduled.
- **Semantic staleness judgment.** Readiness/staleness is a deterministic heuristic, clearly labeled — never a semantic claim presented as truth.
- **Solving BL-06 large-Vault stress.** Discovery honors the existing visited-entry cap; it does not add new large-scale performance work.

## Product principles & invariants honored

- **Local-first / no network.** All analysis is local and deterministic.
- **Ordinary files remain content truth.** Discovery reads managed files read-only; nothing is copied into a second store.
- **Renderer never touches Node/SQLite/fs** (invariant 2). Filesystem discovery runs in the main process behind typed IPC.
- **Determinism where possible** (invariant 7). Pure classification/readiness logic yields byte-identical output for identical input — mirroring `analyzeKnowledgeIntegrity`.
- **Project context is isolated by default** (invariant 5). Analysis is scoped to one project; no cross-project evidence.
- **Models return proposals, never silent mutations** (invariant 3) — upheld trivially: `v0.3.1` produces no proposals and no model output at all.
- **No promotion to canonical state.** There is no code path from analysis output to canonical Vault state.

## Architecture

Same strict one-directional boundary as the rest of Orbit Vault. New surface is **additive and read-only**; no existing channel, table, or invariant changes.

```
Renderer (window.vault.context.* — read-only inspection view)
  → typed IPC ("vault:context:analyze", read-only, no `mutates`)
  → VaultService (packages/vault-core)  — validation + orchestration
  → SqliteVaultRepository (packages/vault-storage) — filesystem discovery over projects/<id>/
  → pure analyzers (packages/vault-core) — classification + readiness + context packaging
```

**Placement rationale (invariant 2 + invariant 7):**
- **Filesystem-touching discovery** lives in `packages/vault-storage` (it already owns `projects/` traversal, the ignore-lists, the 25,000-entry cap, symlink `safeLinkedKind`, and `hashTree`). Discovery reuses these rather than reinventing them.
- **Pure logic** (category classification, Project Truth readiness detection, context selection/packaging) lives in `packages/vault-core` as **pure functions over a plain input struct** — no fs, no SQLite — so it is byte-deterministic and unit-testable exactly like `analyzeKnowledgeIntegrity`.
- **`VaultService`** validates the `projectId` (`assertIdentifier`) and orchestrates: ask the repository for the raw file inventory, feed it to the pure analyzers, return the assembled result.

### `packages/vault-types` — contracts (additive)

New types (final names fixed in the execution plan). Reuses the existing `AiContextPackage` / `AiContextItem` / `AiContextItemKind` (which already includes the `repository_file` kind) verbatim — no change to `v0.3.0` contracts.

- `ProjectEvidenceCategory` — a closed union of **technical-fact** categories only, e.g. `"manifest" | "config" | "schema_migration" | "test" | "documentation" | "project_truth" | "source" | "todo_marker" | "other"`. No category asserts owner intent.
- `ProjectEvidenceItem` — `{ relativePath: string; category: ProjectEvidenceCategory; sizeBytes: number; }` (POSIX relative path, stably ordered). Content is **not** embedded here — the inventory is a manifest of what exists.
- `ProjectEvidenceInventory` — `{ projectId: string; items: ProjectEvidenceItem[]; totalFiles: number; truncated: boolean; }` (`truncated` = the visited cap was hit).
- `ProjectTruthReadiness` — `{ state: "complete" | "partial" | "missing" | "duplicated" | "potentially_stale"; presentDocuments: string[]; missingDocuments: string[]; duplicateDocuments: string[]; stalenessSignals: string[]; }`. `stalenessSignals` entries are labeled deterministic heuristics.
- `ProjectContextAnalysis` — the top-level read-only result: `{ projectId: string; ruleVersion: string; inventory: ProjectEvidenceInventory; readiness: ProjectTruthReadiness; contextPackage: AiContextPackage; generatedAt: string; }`.
- IPC contract entry on `VaultRendererApi`: a read-only `context: { analyze(projectId: string): Promise<ApiResult<ProjectContextAnalysis>> }` (naming/shape finalized in the plan).

### `packages/vault-core` — pure analyzers + service orchestration

- `PROJECT_CONTEXT_RULE_VERSION` — version tag stamped into every result (mirrors `INTEGRITY_RULE_VERSION`), so a byte-identical-output test can assert stability.
- `classifyEvidence(input): ProjectEvidenceInventory` — pure. Maps a raw discovered file list (relative path + size) to categorized, **stably sorted** items. Category detection is rule-based (filename/extension/path patterns — e.g. `package.json`/`pnpm-workspace.yaml` → manifest, `*.test.ts` → test, `.orbit/*.md` → project_truth, `TODO`/`FIXME` markers already surfaced by discovery → todo_marker).
- `detectProjectTruthReadiness(input): ProjectTruthReadiness` — pure. Given which `.orbit/` documents are present/duplicated and simple deterministic signals, classify the stack state. The expected `.orbit/` set is the canonical eight (PROJECT, PRODUCT_SPEC, ARCHITECTURE, DECISIONS, ROADMAP, CURRENT_PHASE, BACKLOG) + `AGENTS.md` + `README.md` as recognized-but-not-required context. Staleness is heuristic only (e.g. a present-but-empty truth doc) and always labeled.
- `buildProjectContextPackage(input): AiContextPackage` — pure. Selects a **targeted** subset of evidence (not the whole repo) and produces `AiContextItem`s via `createAiContextPackage`, each with a `sourceRef` = the file's relative path so it stays inspectable. Selection is deterministic and bounded (caps count/size; over-inclusion is a correctness failure per the acceptance criteria).
- `VaultService.analyzeProjectContext(projectId)` — validates the id, calls the repository discovery method, runs the three pure analyzers, and returns `ProjectContextAnalysis`. Read-only; performs no writes.

### `packages/vault-storage` — filesystem discovery (read-only)

`SqliteVaultRepository` gains a **read-only** discovery method that walks `projects/<id>/` and returns a raw file list (relative POSIX path + size + a cheap flag for lines that match a `TODO`/`FIXME` marker, if we choose to detect markers at discovery time). It **reuses**:
- `IGNORED_DIRECTORIES` / `IGNORED_FILES` (the existing reconciler ignore-lists) — same ignore semantics as reconcile.
- The **25,000 visited-entry cap** and `safeLinkedKind` symlink constraint from `reconcileProject` — extracted/shared so discovery and reconcile cannot drift. Hitting the cap sets `truncated: true` (discovery does **not** throw the way reconcile's hard limit does — analysis degrades gracefully rather than failing).
- `isSafeRelPosixPath` for path safety.

Discovery never leaves the project boundary and never reads file *contents* into the result beyond what packaging needs (packaging reads targeted files' content in a bounded, read-only way in the service/storage layer — exact split finalized in the plan).

### `apps/vault-desktop` — read-only inspection surface

- `electron/main`: register `vault:context:analyze` via the existing `handle(channel, op, mutates=false)` helper — **read-only (no `mutates`)**, so it does not emit `vault:changed`.
- `electron/preload`: expose `window.vault.context.analyze(projectId)` through the existing `call<T>` wrapper on the frozen surface.
- `renderer`: a **minimal, read-only inspection view** that runs the analysis for the current project and displays the evidence inventory (grouped by category), the Project Truth readiness verdict, and the constructed context package (items + source refs). No edit/approve/generate controls.

## Acceptance-criteria → test mapping

Mirrors `.orbit/CURRENT_PHASE.md` "Acceptance criteria (v0.3.1)". New suite `tests/phase3-project-context.test.ts` (name finalized in the plan):

1. **Deterministic inventory** — same fixture tree → identical, stably-ordered `ProjectEvidenceInventory`; serialized result byte-identical across two runs (mirrors the integrity byte-identical test).
2. **Ignore rules & boundary** — fixtures containing `node_modules`, `.git`, `dist`, `vault.db*` are excluded; traversal stays in-project; symlink escaping is refused; exceeding the cap sets `truncated: true`.
3. **Technical-fact classification** — representative files land in the right `ProjectEvidenceCategory`; no category encodes owner intent.
4. **Readiness detection** — fixtures for each state (`complete` full `.orbit/` set; `partial` missing docs; `missing` no stack; `duplicated` a doubled doc; `potentially_stale` present-but-empty) return the expected `state`, with staleness labeled heuristic.
5. **Targeted context package** — assembled `AiContextPackage` reuses `v0.3.0` contracts, every item has a `sourceRef`, and it is provably **not** the whole repository (bounded count/size; a large fixture is not dumped verbatim).
6. **No mutation / no generation** — analysis performs no writes (repository state unchanged before/after, like the integrity "performs no mutation" test) and produces no proposal and no model call.
7. **Boundary invariants** — pure analyzers are fs/SQLite-free and byte-deterministic; discovery is project-isolated (another project's files never appear).
8. **Read-only IPC contract** — `scripts/phase2-lifecycle-ui-regression.mjs` asserts `vault:context:analyze` exists, is read-only (no `mutates`), and is wired through preload to `window.vault.context.analyze`.

## Risks (from `.orbit/CURRENT_PHASE.md`)

- **Scope creep into `v0.3.2`** — stop at analysis + packaging; produce no Truth *content*.
- **Cross-platform determinism** — normalize path separators/ordering (POSIX relative paths, explicit sort) so invariant 7 holds on Windows and POSIX.
- **Boundary leakage** — keep all fs in storage/main; keep classification pure in core.
- **Heuristic staleness mistaken for truth** — label staleness signals as heuristic; never present as canonical.
- **Large repositories** — honor the shared visited cap; degrade to `truncated: true`, don't freeze (defer BL-06).
- **Context over-inclusion** — "targeted, not whole-repo" is a tested correctness requirement, not a preference.
